# feature-log — 機能追加時のドキュメント整備手順

機能を追加・変更したら、**コミット前に必ず**本手順でドキュメントを更新する。
（ユーザー恒久指示: 追加機能は機能要項に、トラブル/判断は開発規則に残す）

## 手順

1. **機能要項を更新** — `docs/機能要項.md`
   - 対応するカテゴリ表に行を追加/更新（機能ID `F-xxx`, 名称, 状態 ✅/🟡/⬜, 実装箇所）
   - 末尾「追加機能ログ」に `YYYY-MM-DD 機能ID 概要` を1行追記
   - その回の目玉は1つだけ太字にする

2. **トラブル/判断があれば開発規則を更新** — `docs/開発規則.md`
   - 「トラブル/決定ログ」表に `| MM-DD | 事象 | 原因 | 対処/規則ID |` を追記
   - 恒久的に守るべき事項は `R-xxx` 規則として追加
   - **踏んだバグは必ず残す。** 何が起きたか・なぜか・今後どうするかの3つを書く

3. **要件に影響するなら要件定義を更新** — `docs/要件定義.md`
   - スコープ / やらないこと / 非機能 / 用語に変更があれば反映

4. **整合チェック**
   - typecheck とテストが緑であることを確認
   - 新しい純粋ロジックには単体テストを追加する
   - 画面を変えたなら、実際にブラウザで通して確認する

5. **スキルを新設した場合** — `docs/スキル一覧.md` に名前・目的・使いどころを追記

## 参照

- 機能ID体系: `docs/機能要項.md` の冒頭
- 規則の書き方: `docs/開発規則.md` の冒頭
